    • [M1] Assume Breach: 查無紀錄 ≠ 無害 (防範 T1070 竄改)。

    • [M3] Asymmetric Cost: 漏報代價遠高於誤報，安全覆寫優先。
    • [M4] Pyramid of Pain: 鎖定 TTPs 而非易變的 Hash/IP。
    • [M5] Human-in-the-Loop: AI 作為副駕駛，主動呈請裁決。

[SEC 3] 攻擊鏈規則 (R1-R5) 與升級協定 3.0
  • [3.1 攻擊鏈高風險硬約束 (R1–R5)]
    • [R1 終端衝擊]: Exfiltration (外洩) / Impact (破壞) → 強制高風險。
    • [R2 憑證擴散]: Credential Access + Lateral Move → 優先升級。
    • [R3 入侵常駐]: Initial Access + Persistence → 關聯攻擊標記。
    • [R4 抹除紀錄]: Indicator Removal (T1070) → 防禦規避標記。
    • [R5 多階段鏈]: 涵蓋 $\ge 3$ 個不同戰術階段 → 威脅層級提高。
  • [3.2 四大人工作業升級邊界 (Algorithm 2)]
    符合以下任一條件，系統強制將狀態標記為 NEEDS_HUMAN_REVIEW：
    1. [低信心度]: 綜合判定信心度 $< \tau$（預設 0.80）。
    2. [結論衝突]: ML 預測與 LLM 推理方向相反 ($\text{Argmax } p \ne \text{Argmax } q$)。
    3. [後段攻擊]: 命中 R1–R5 高風險規則之一。
    4. [證據不足]: 工具呼叫耗盡預算上限 $B$ 且不確定性未消除。
  • [3.3 三大專業爭論 (C1–C3)]
    • [C1]: ML 穩定吞吐 vs LLM 脈絡推理 (本案: 融合互補)。
    • [C2]: 自動化自滿 vs 人類監督 (本案: 輸出可驗證證據鏈)。
    • [C3]: Benchmark 偏差 vs 真實遙測 (本案: 雙公開集 GroupKFold)。
